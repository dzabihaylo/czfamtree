## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Clerk-issued JWT -> Postgres `auth.jwt()` | The JWT's `sub` claim is the authz principal; a successful cross-table RLS check must route through this |
| authenticated caller -> `bootstrap_tree` RPC | SECURITY DEFINER bypasses RLS inside the function; the function body must reassert the caller identity |
| table owner (postgres) -> data in the 4 tables | `force row level security` closes the table-owner bypass (defense-in-depth) |
| `supabase db push` operator -> cloud DB | The person running the CLI can apply any migration; `SUPABASE_ACCESS_TOKEN` must be scoped per-project |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | RLS policy using `auth.uid()` silently returning NULL | mitigate | Every RLS policy uses `(select auth.jwt()->>'sub')` — verified by grep: `grep -c "auth.uid()" supabase/migrations/*.sql` MUST return 0 (Anti-Pattern #3) |
