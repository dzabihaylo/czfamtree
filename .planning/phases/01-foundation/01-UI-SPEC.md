# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1 (Foundation). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** `design_handoff_family_tree/source/styles.css` (handoff `:root` CSS variables). Per PROJECT.md DESIGN-03, Tailwind v4 `@theme` maps handoff tokens 1:1 — no drift permitted.
>
> **Phase 1 UI surfaces (only these are in scope):**
> 1. Sign-in screen (split 50/50, brand + 3-provider stack + illustration)
> 2. Shell / topbar on first authenticated load (brand, tree title, user avatar)
> 3. Seeded tree route with a single "You" `PersonNode` visible (rendering details — positioning, SVG edges, pan/zoom — deferred to Phase 2)
> 4. Inline tree rename (topbar tree title becomes a text input on click)
> 5. Tree switcher (dropdown of owned + invited trees, "+ New tree" action)
> 6. User menu dropdown with "Sign out" (anchored to avatar in topbar)
>
> Canvas pan/zoom, radial menu, side panel, auto-save pill, toolbar, toasts, share modal, realtime — ALL deferred to later phases. Phase 1 renders a static seeded node only.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom Tailwind v4 `@theme` mapping handoff CSS variables) |
| Preset | not applicable — shadcn rejected for Phase 1 |
| Component library | none (hand-rolled primitives; Clerk `<SignIn />` hosted component for auth) |
| Icon library | lucide-react 1.8.0 (per STACK.md) |
| Font | Inter 400/600 (sans) + JetBrains Mono 400 (mono) — both via `next/font/google` |
| Primary focal point | `.login-headline` — 48px display type is the eye-entry point on the sign-in screen; topbar tree title is the focal point post-auth |

**Why no shadcn:** The handoff is a deliberately Swiss / brutalist design system — sharp 0px corners, hairline 1px borders, hard drop-shadows (`4px 4px 0 var(--ink)`, no blur), monospace UI micro-copy, OKLCH colors. shadcn's defaults (rounded-md, subtle soft shadows, neutral Radix primitives) would fight the handoff's identity on every component. Per DESIGN-03 the handoff is pixel-parity target — introducing shadcn creates drift that auditor would reject downstream. Any future reusable primitives (Dropdown, Modal, Toast) will be hand-rolled against the handoff `styles.css` and tested against the HTML prototype.

**Clerk component styling:** Phase 1 uses Clerk's `<SignIn />` hosted component with `appearance.variables` mapped to handoff tokens (`colorPrimary: oklch(0.18 0.008 80)`, `borderRadius: '0'`, `fontFamily: 'Inter'`, etc.) and `appearance.elements` overrides to match the google-btn style (1px ink border, 4px-offset hard shadow on hover, 0px radius, matching button padding from component constants below).

## Typography

Four sizes + two weights (Swiss high-contrast: hierarchy carried by size, not by a third weight), plus mono overlay:

| Role | Font | Size | Weight | Line Height | Used In |
|------|------|------|--------|-------------|---------|
| Display (headline) | Inter | 48px | 600 | 1.05 | `.login-headline` "Every name, a branch. Every branch, a story." |
| Body | Inter | 14px | 400 | 1.5 | `.login-sub` tagline, `.login-brand` "Family Tree" wordmark, `.field-input`, default UI body text |
| Label / emphasis | Inter | 13px | 600 | 1.3 | `.btn` / `.google-btn` button labels, `.topbar-title strong`, tree switcher item, user menu rows |
| Mono micro | JetBrains Mono | 11px | 400 | 1.2 | `.feat-tag`, `.topbar-title` meta ("· N people"), `.login-foot`, `.invite-avatar` initials, section headers (`YOUR TREES`, `SHARED WITH YOU`, `GETTING STARTED`) |

**Scale rationale (revision note):**
- Collapsed handoff's 15px `.login-sub` body-large down to 14px body (single body size, cleaner hierarchy — 14px with 1.5 line-height still reads comfortably at the handoff's 420px max-width).
- Collapsed handoff's 10px + 11px mono pair into a single 11px mono micro (functional UI text wins over decorative; 10px was borderline readable on non-retina).
- Dropped weight 500 entirely. Every former 500 use-case (button labels, topbar-title strong, tree switcher items) promotes to 600 — Swiss aesthetic favors high-contrast two-weight system (regular body + heavy emphasis). Where 500 was previously used for body text with slight emphasis, color (`--ink` vs `--ink-2`) now carries that differentiation.

**Letter-spacing:**
- Display/headline (48px): `-0.025em` (tight)
- Body (14px): `-0.005em` (very slightly tight)
- Label (13px): `-0.005em`
- Mono uppercase labels (11px): `+0.12em` (wide, Swiss caps)

**Font families:**
- Sans: `Inter, 'Helvetica Neue', Helvetica, Arial, sans-serif`
- Mono: `'JetBrains Mono', ui-monospace, 'SF Mono', Menlo, monospace`

Both loaded via `next/font/google` with `subsets: ['latin']` and CSS variable names `--font-sans` / `--font-mono`, exposed to Tailwind `@theme` as `--font-sans` and `--font-mono`. Only weights 400 and 600 loaded for Inter (skip 500 to save ~8kB per subset). Only weight 400 loaded for JetBrains Mono.

**Font-feature-settings:** `'ss01', 'cv11'` on `body` (per handoff — Inter stylistic set 1 + character variant 11 for geometric single-storey `a`).

**Accent reserved for:**
1. **Focus ring** on keyboard-focused interactive elements (`:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`)
2. **Input border** when focused (`.field-input:focus { border-color: var(--accent) }`) — e.g. inline tree-rename input
3. **User avatar fill in topbar** (owner color for current signed-in user, matching handoff `app.jsx` where `DZ` avatar is `oklch(0.52 0.14 250)`)
4. **Login illustration spouse-connector line** (decorative SVG inside `.login-art`, fixed per handoff)

**Never accent in Phase 1:**
- Primary CTA ("Continue with Google" / "Continue with Apple" / "Continue with email") — these use `var(--ink)` border on `var(--bg-card)` fill, with `4px 4px 0 var(--ink)` hover shadow. The handoff deliberately withholds accent from the primary-action to keep Swiss restraint.
- Link-share toggle (Phase 5), toast backgrounds (Phase 3), etc.

**Dark mode:** Not supported in v1. The handoff is light-mode only; no dark-mode tokens exist. Defer to v2.

## Interaction Contract

Phase 1-specific interactions. Each entry specifies trigger → feedback → final state.

**Primary focal point:** On the sign-in screen, `.login-headline` (48px display) is the eye-entry point — it's the largest type on the screen, left-aligned at the top of the content column, and carries the brand's core promise. Post-auth, the topbar tree title (Inter 13px 600 with meta suffix) is the focal point because it's the only actionable element at the top of the app shell and the state indicator for "which tree am I in right now."

### Sign-in flow

| State | Visual | Behavior |
|-------|--------|----------|
| Initial | Three buttons vertically stacked, 12px gap (md token), each 100% width of content column (max 260px). Each button: 1px ink border, white fill, 0px radius, `8px 14px` padding (handoff component constant), 13px Inter 600 label, 18px leading icon. | Click any button → Clerk hosted flow opens (Google/Apple in new OAuth popup; email in same-page modal with Clerk's magic-link form) |
| Hover | Button translates `-2px, -2px`, shadow `4px 4px 0 var(--ink)` appears | Per handoff `.google-btn:hover` |
| Active/loading (per-button) | Spinner replaces icon; label becomes `Signing in…`; button is `disabled` (cursor default, opacity unchanged) | During Clerk OAuth roundtrip |
| Keyboard focus | Outline `2px solid var(--accent)`, offset 2px | Per handoff global `:focus-visible` |
| Success | Browser navigates to `/` (or originally-requested URL if invited via share-link — Phase 5) | Handled by Clerk after token exchange |

### First-sign-in auto-tree-creation

On the FIRST authenticated load after Clerk's `userCreated` signal, a server action creates a new `trees` row (name `My family tree`, owner = Clerk `sub`) and a seed `people` row (`name: 'You'`, `is_me: true`, `x: 0, y: 0`, `tree_id: new tree.id`). No UI confirmation — the user lands directly at `/tree/{newTreeId}` with one node visible. This is a one-time race — the server action is idempotent on `(owner_user_id)` where `tree_members.count() = 0`.

### Topbar layout (52px tall)

Left to right:
1. `CZ` brand mark (20×20 ink square, mono 11px white glyph) + `Family Tree` wordmark (Inter 14px 600, -0.005em tracking). Gap 12px (md). Fixed.
2. Vertical rule 1px `--rule`, 24px tall, 16px horizontal margin.
3. Current tree title (Inter 13px 600, `--ink`) with meta suffix "· N people" (mono 11px, `--ink-3`). Clickable for inline rename. Hover: background tints to `--bg-soft`.
4. Tree switcher chevron (lucide `ChevronDown`, 13px, `--ink-2`). Click opens dropdown anchored under title.
5. Flex-grow spacer.
6. User avatar (32×32 circle, initial-in-mono, fill = hash(userId) → choose from `oklch(0.52 0.14 250)` / `oklch(0.62 0.13 150)` / `oklch(0.72 0.14 75)` palette). Click opens user menu dropdown anchored under avatar.

Share button, presence stack, Sheet-sync button — NONE in Phase 1 (deferred to Phase 5). Topbar gets these later.

### Inline tree rename

Trigger: click on tree title text node.
Behavior:
1. Title text node is replaced by an `<input type="text">` with `value = tree.name`, `maxLength = 80`, auto-focused, text auto-selected.
2. Input has `.field-input` styling: 1px `--rule` border, 0px radius, 8×12px padding (sm × md tokens), 14px Inter 400, accent border on focus.
3. User types; changes held in local state only.
4. Commit triggers: `Enter` key OR `blur`.
5. On commit: call `renameTreeAction(treeId, newName)`. Optimistic local state update. On server error, silently revert (Phase 1 has no toast infrastructure — this is logged only).
6. On `Escape`: abandon, revert to pre-edit name, exit edit mode.
7. Empty name: treated as revert (UX: "don't let user destroy their own title by clearing it").

### Tree switcher dropdown

Trigger: click chevron next to tree title (or click the tree title meta area, depending on click-position — title text triggers rename, chevron triggers switcher; clear 4px deadzone between them).

Structure (vertical stack, 280px wide, anchored under chevron, offset 4px below topbar):
1. Outer container: `--bg-card` fill, 1px `--ink` border, `4px 4px 0 var(--ink)` hard shadow, 0px radius, 4px internal vertical padding.
2. Section header `YOUR TREES` (mono 11px `--ink-3`, caps, 0.12em tracking, 12px horizontal + 8px top padding, 4px bottom padding).
3. List of owned trees. Each row: 12×16px padding (md × lg tokens), 13px Inter 600, hover bg `--bg-soft`. Active tree has a 4px left-border accent (2xs token). Click → navigate to `/tree/{id}`.
4. 1px `--rule-soft` divider.
5. Section header `SHARED WITH YOU` — hidden if list empty.
6. List of invited trees (same row style).
7. 1px `--rule-soft` divider.
8. Action row `+ New tree` — Inter 13px 600, with lucide `Plus` icon 13px. Hover bg `--bg-soft`. Click → call `createTreeAction()` → redirect to new tree.

Close triggers: click outside (backdrop detection via portal), Escape key, selecting an item.

### User menu dropdown

Trigger: click avatar.

Structure (vertical stack, 240px wide, anchored under avatar, right-aligned to avatar):
1. Outer container: identical Swiss-card styling (card bg, ink border, hard shadow, 0px radius, 4px padding).
2. Header block (non-clickable, 12×16px padding): `{displayName}` (Inter 13px 600 `--ink`) + `{email}` (mono 11px `--ink-3`). 1px `--rule-soft` bottom divider.
3. Row: `Sign out` (Inter 13px 600 `--ink`, with lucide `LogOut` icon 14px `--ink-2`). 12×16px padding. Hover bg `--bg-soft`. Click → Clerk `signOut()` → redirect to `/sign-in`.

Close triggers: click outside, Escape, selecting "Sign out".

### Keyboard interaction matrix (Phase 1 only)

| Key | Context | Action |
|-----|---------|--------|

These were not directly answered by REQUIREMENTS, ROADMAP, or design handoff. Default decisions above are defensible; flag if the planner wants to override:

1. **Topbar height: 52px vs 56px.** Handoff `.topbar { height: 52px }`. REQUIREMENTS.md PANEL-02 says "56px topbar". Phase 1 locks **52px** per DESIGN-03 pixel-parity mandate. Phase 2 CANV-01 ("canvas fills viewport below the 56px topbar") must be updated to 52px during planning, OR the handoff must be overridden.
2. **Tree rename persistence on blur error.** Phase 1 silently reverts because no toast system exists yet. Acceptable given low-risk idempotent operation. Phase 3 will upgrade this when toast infra lands.
3. **User avatar color assignment.** Deterministic hash of `userId` → palette of 4 accent-family OKLCH colors (the three shown in handoff app.jsx + one additional). Confirmed palette: `oklch(0.52 0.14 250)` (accent indigo), `oklch(0.62 0.13 150)` (success green), `oklch(0.72 0.14 75)` (warning gold), `oklch(0.70 0.10 300)` (lilac).
4. **First-run tree name.** `My family tree` — neutral, un-opinionated, user can rename immediately. Alternative considered: `{userFirstName}'s family tree` — rejected because Clerk might not expose first name on email sign-in.
5. **Clerk `<SignIn />` vs custom buttons.** Locked as **Clerk hosted `<SignIn />` with appearance overrides**. Custom buttons calling Clerk's programmatic `signIn.create()` would require 3x more code and risk divergence from Clerk's maintained OAuth flows. Appearance API covers the Swiss styling need.
