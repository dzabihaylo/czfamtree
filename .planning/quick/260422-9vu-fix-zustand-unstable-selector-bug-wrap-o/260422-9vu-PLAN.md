<objective>
Fix the Zustand 5 unstable-selector infinite render loop that crashes the tree page on load.

Two selectors allocate a fresh `Object.keys(s.people)` array on every call. Zustand 5 uses `useSyncExternalStore`, which requires snapshot identity stability under `Object.is`. A new array reference each render → React detects snapshot churn → infinite re-render loop → `Maximum update depth exceeded`.

Purpose: restore the ability to load the tree page without a runtime crash. This is a blocker for any Phase 2 verification and for starting Phase 3.

Output: two files edited (≤ 6 LOC changed total), no behavior change, no new dependencies (Zustand 5.0.12 already ships `zustand/shallow`).
</objective>

<bug_details>
**Runtime symptoms (from bug_context):**
```
[browser] The result of getServerSnapshot should be cached to avoid an infinite loop
    at PanZoomWrapper (components/canvas/PanZoomWrapper.tsx:105:33)
  const peopleIds = useTreeStore((s) => Object.keys(s.people));

[browser] Uncaught Error: Maximum update depth exceeded.
    at TreeCanvas (components/canvas/TreeCanvas.tsx:72:7)
```

**PanZoomWrapper.tsx line 105 (the array case):**
```ts
const peopleIds = useTreeStore((s) => Object.keys(s.people));
```
`Object.keys(...)` returns a brand-new array reference every call. Zustand's default `Object.is` equality check sees `prev !== next` and forces a re-render, and `useSyncExternalStore` re-invokes the selector, detects another new reference, and loops.

**TreeCanvas.tsx line 46 (the primitive case):**
```ts
const peopleCount = useTreeStore((s) => Object.keys(s.people).length);
```
The return is a number (primitive), so `Object.is(prev, next)` returns `true` when the count is unchanged — however React's `useSyncExternalStore` still calls the selector during render to cross-check the cached snapshot, and the fresh `Object.keys(...)` allocation inside triggers the `getServerSnapshot should be cached` dev warning on SSR/hydration. The cleaner fix: subscribe to the stable `s.people` record reference and derive `.length` outside the selector. No allocation, no warning.
</bug_details>
